# Per-benchmark fixed iteration counts for instrumentation PGO collection.
#
# Each "Name=N" line fixes the exact iteration count pgo-collect-instr.sh runs
# for that benchmark. This freezes the merged profile's workload weights: a
# wall-clock budget made the per-benchmark iteration counts drift with machine
# conditions, flipping LLVM layout decisions between otherwise identical
# collections (measured ~3% on Benchmark_Unmarshal_KubePods_Velox).
#
# The table is committed, so the same tree collects a byte-identical profile
# on every machine. Entries are calibrated against the INSTRUMENTED binary;
# regenerate after adding or changing benchmarks:
#
#   PGO_ITERS_REGEN=1 make pgo-instr-collect MODULE=ndec
#
# Calibration target (default 6s per benchmark) preserves the historical
# 3s x count=2 equal-time weighting semantics. To up-weight a workload,
# raise its entry, re-collect, and gate the result (make pgo-gate MODULE=...).
# Regen only touches entries matched by the active filters; entries for the
# other module's benchmarks are preserved.
